# Changelog

Short notes on what changed in Qali (called LiNaK until November 2026). Newest first.

## Latest

### Fixed
- **Polarizabilities left out the valence photoionization continuum.** The sums over bound np lines (to n = 50) miss the oscillator strength that goes to the continuum: 0.24 for Li 2s, 0.01–0.05 for Na–Fr. Li α(0) came out 0.8 % low and C₆ 2.6 % low.
  - New `physics/valence_continuum.py`: the bound state and the energy-normalised continuum εl′ in the same Marinescu model potential as the orbital page, df/dε from the j-resolved E1 matrix element, integrated from threshold to 20 Hartree plus an ε^−7/2 tail, as pseudo-lines (`source: continuum`, 10 % uncertainty). Checked against the bound series: df/dε at threshold equals the limit of f_n n*³ to 2 %.
  - Used by Polarizability, Tweezer and the Blackbody ground and excited networks. Neutral Li–Fr only; Fr p → εd is left out (Fr d is not fitted).
  - Results:

    | | α(0) before → now | C₆ before → now | C₆ reference |
    |---|---|---|---|
    | Li | 162.82 → 164.09 (164.11) | 1357.6 → 1393.0 | 1393.39(16) |
    | Na | 162.61 → 162.68 | 1556.8 → 1559.1 | 1556(4) |
    | K | 289.54 → 289.59 | 3878.8 → 3881.6 | 3897(15) |
    | Rb | 318.69 → 318.80 | 4698.4 → 4703.1 | 4691(23) |
    | Cs | 399.62 → 399.76 | 6846.9 → 6854.7 | 6851(74) |
    | Fr | 315.02 → 316.05 | 5162.5 → 5214.0 | 5256(89) |

    Li 2p₁/₂ α(0) 119.5 → 127.1 a.u. (126.97 calculated).
  - Above a state's photoionization threshold Re α needs a principal value over the continuum, which a sum over lines cannot give: α(λ) is now not evaluated there (NaN in the code, no curve on the pages). Magic wavelengths below the excited state's threshold (Li < 350 nm, Na < 408 nm, K < 455 nm, Rb < 474 nm, Cs < 494 nm) are no longer listed; they were computed without the continuum.
  - Bundled outputs regenerated with `tools/regenerate_all.py --refresh-bundled`; the Na regression anchor moves to α(0) 162.678, C₆ 1559.08. The same run refreshes the hyperfine pages (current notes) and the Fr 7d lifetimes, which the restored bundle had from an older run: 7d₃/₂ 73.6 ns and 7d₅/₂ 67.7 ns, the published values.
- **DHF: point-nucleus intruder in the core.** With no isotope mass the DHF model used a point nucleus, and at Fr the DKB basis then gives a κ = +1 state at −11702 a.u., which replaced the 2p₁/₂ core orbital. The model now always uses a finite nucleus (A ≈ 2Z + 0.006Z² when no isotope is given), and the core SCF skips any positive-energy eigenvalue more than 2 % below the point-Coulomb floor of its channel (`dirac_basis.dirac_floor`); skipped states are reported as `basis_intruders`. Brueckner orbitals use the same filter.
- **Feshbach: ⁸⁷Rb had one entrance channel.** The file held the four s-wave lines of |1,+1⟩ + |1,+1⟩ only.
  - Added the d-wave lines of that channel with Δ ≥ 0.2 mG (Marte et al. 2002, Table I: 391.49, 551.47, 632.45, 719.48, 831.29 G), which are poles of a(B) like the Cs d- and g-wave lines.
  - Added six mixed-spin channels near 9 G and 18 G (Kaufman et al., PRA 80, 050701 (2009)), including the |1,+1⟩ + |2,−1⟩ line at 9.10 G (Erhard et al. 2004).
  - These channels can relax, so the resonance has an inelastic width γ: a = a_bg[1 − Δ/(B − B₀ − iγ/2)]. The resonance table has a γ column and a(B) is drawn as Re a, which stays finite (|Re a − a_bg| ≤ |a_bg|Δ/γ ≈ 40 a₀ at 9.10 G) and has no zero crossing when γ > Δ.
- **Bundled hyperfine constants restored.** `Na`, `K`, `Rb` and `Cs_hf_constants.json` had lost the measured atomic g_I′ and ground-state g_J (an older copy from an output folder was put over them), so the hyperfine pages fell back to the bare-nucleus g_I. They are back as of 2026-11-11.
- **`tools/regenerate_all.py --refresh-bundled`** updates the bundled example data safely: it runs every stage in a fresh temporary folder and copies back only the files the stages wrote, never the input files. Copying an output folder over `resources/data_json` by hand brings in old copies of the input files.

### Changed
- **LiNaK is now Qali.** The app, the Python package (`qali`), the commands (`qali`, `qali-gui`), the executable, the environment variables (`QALI_PROJECT_ROOT`, `QALI_SETTINGS_FILE`), the per-user data folder (`Qali`) and the output folder inside a source checkout (`.qali`) carry the new name. The licence, the DOI and the repository history are unchanged.
  - Nothing made under the old name is lost: `linak` and `linak-gui` still start the app (with a one-line note), `import linak` gives the `qali` modules (with a `DeprecationWarning`), `LINAK_PROJECT_ROOT` and `LINAK_SETTINGS_FILE` are read when the new variables are unset, saved settings are copied over on first start, and an existing `LiNaK` data folder or `.linak` output folder keeps being used until a `Qali` / `.qali` one exists.
  - In a source checkout, run `uv sync` once after updating. It removes the old `linak` install, which otherwise keeps `import linak` and the `linak` command on the old code.
- **New logo.** A saltwort sprig with an ember ("alkali" comes from the Arabic *al-qalī*, the ash of that plant). It is the window, taskbar and executable icon, the wordmark in the toolbar and a splash screen while the app starts. The main window and taskbar always show the app icon; on Windows the app now has its own taskbar identity, so the taskbar no longer shows the Python launcher's icon. The ember of the toolbar wordmark and of the empty-viewer sprig takes the theme's accent colour (green in Light).
- **Icons follow the species.** The ember on a species' dialogs (Properties, Set up, Hyperfine constants, Extrapolation, Delete) and on the species list takes that species' colour: the flame-test colour for Li, Na, K, Rb and Cs, grey for Fr, the logo's orange for everything else. Right-click a species > **Properties...** > **Icon colour** changes it.
- **New theme: Qali** (View > Theme, and Edit > Preferences > Appearance): a sage-slate green-grey with the ember as accent. Every panel colour is built from one **Qali theme base colour**, which Edit > Preferences > Appearance lets you change; the other colours can be edited there like those of Dark and Light.
- **Toolbar, species list and empty viewer.** The wordmark replaces the "LiNaK" label, followed by the current species in bold (no "Current species:" prefix). Species chips are compact, each with a small ember. The empty viewer shows a faint sprig.
- **Accent colour.** Dark now uses the logo's ember orange in place of the green for buttons, check marks, links and the stage-done dot. Light keeps its green. A colour you set yourself in Preferences is kept.

### Fixed
- **Orbital viewer: wrong radial functions below n* ≈ 3.** The radial part was the Coulomb function at n*, continued as r^ℓ inside the core, so states lost their inner nodes (Na 3s showed 0 instead of 2) and low states had the wrong shape.
  - Li–Fr now use the Marinescu ℓ-dependent model potential (core screening, core polarization, spin–orbit with the extrapolation model's fitted p scale), solved for n − ℓ − 1 nodes. Every Li–Fr model state has the right node count; the eigenvalue matches the level's n* to 5×10⁻⁴ (Na), 9×10⁻⁴ (K), 2×10⁻³ (Fr), 3×10⁻³ (Rb), 4×10⁻³ (Li) and 6×10⁻³ (Cs).
  - One-electron species use the analytic hydrogenic function. Everything else, and Fr d/f (not fitted), keeps the Coulomb function, labelled "outside the core only". `--radial coulomb` forces it everywhere.
- **Orbital viewer: ground state missing.** The list was built from the excitations only, so Na started at 3p. The ground state is now listed first.
- **Orbital viewer: n\* from the ℓ-averaged defect.** Fine-structure partners shared one n*. n* now comes from each level's own binding energy, n* = z√(R_M/binding).
- **Ion-core polarisability at nonzero frequency.** The core was one line holding all N_core electrons' oscillator strength (Thomas–Reiche–Kuhn) at √(N_core/α_c), about 2 a.u., so its α(iω) fell off too slowly. C₆ came out 2–8% high for Rb, Cs and Fr, although α(0) was exact.
  - The core is now its Dirac–Hartree–Fock + RPA response, from a bundled table (`resources/core/core_polarizability.json`, built by `tools/make_core_polarizability.py`). The table stores 15–38 lines per element and is scaled so α_c(0) matches the core-polarisability table in Preferences.
  - Checks:
    - static RPA α_c: Li⁺ 0.1894, Na⁺ 0.9456, Cs⁺ 15.80, Fr⁺ 20.42 a.u., against relativistic RPA 0.1894, 0.9457, 15.81, 20.4;
    - ξ²α_c(iξ) tends to N_core (the sum rule RPA restores);
    - the pseudo-spectrum reproduces the RPA solved at real frequency to 10⁻⁵.
  - C₆ against Derevianko et al. (2010):

    | | Na | K | Rb | Cs | Fr |
    |---|---|---|---|---|---|
    | Before | +0.12% | +0.14% | +2.0% | +3.6% | +7.7% |
    | Now | +0.05% | −0.47% | +0.18% | +0.01% | −1.8% (1.1σ) |

    Rb's 4698.4 a.u. matches the measured 4698(4).
  - α(0) and the near-IR α(λ) are unchanged; magic wavelengths move by under 0.15 nm.
  - Feshbach ā follows C₆^{1/4} (Cs 97.3 → 96.5 a₀).
  - An element missing from the table (a species you add) keeps the one-line model.
  - Rerun Polarizability (then Tweezer, Feshbach and Compare) for your own data. The bundled Polarizability, Tweezer, Feshbach and Compare outputs are regenerated.
- **Tweezer trap depth left out the core.** `tweezer_core` dropped the core channels from Re α as well as from the scattering, so the trap depth lacked the core polarisability (1.4% for Cs at 1064 nm). The core now counts in the depth, with no scattering width.
- **Heteronuclear C₆ from a combining rule.** The C₆ matrix filled its off-diagonal pairs with the Tang combining rule on static α, which is 1–3% off (Rb–Cs, K–Cs). Pairs are now computed like the homonuclear C₆, by Casimir–Polder from each atom's own α(iω): C₆^AB = (3/π)∫α_A(iω)α_B(iω)dω. The C₆ integral also gains the analytic tail beyond its cutoff (a 10⁻⁵ change).
- **Fr reference C₆ was unsourced.** `C6_EXPT['Fr']` was 5500 a.u., which no publication gives. It is now 5256(89) a.u. (Derevianko et al. 1999, 2010), also in the bundled `Fr_polarizability.json`.
- **Feshbach: Cs background scattering length.** `Cs_feshbach.json` used the triplet scattering length a_T = 2858 a₀ as the background of the |3,+3⟩ + |3,+3⟩ channel, so a(0) came out at −3950 a₀ instead of the measured −2490 a₀ (Kraemer et al. 2006). The channel now follows the published fits (below).
- **Feshbach: d- and g-wave lines left out of a(B).** "d-wave" names the closed-channel molecular state; with an s-wave entrance channel it is still a (narrow) pole of the s-wave scattering length, as are g-wave states. They were drawn as markers only. Even-ℓ resonances now enter a(B); odd-ℓ (p, f) ones still do not.
- **Feshbach: ⁶Li zero crossings.** The local fits of Zürn et al. put the |1⟩ + |2⟩ zero at 569.9 G; the measured one is at 527.5 G. ⁶Li now uses their coupled-channel table (zero at 527.3 G).
- **Model f-value uncertainty ignored the Preferences table.** Preferences > Tables and variables > Uncertainty model has DHF and Brueckner rows; Polarizability used them, but Lifetimes gave model lines a fixed 5%. Lifetimes now reads the same table (default still 5%).
- **Spectrum line heights.** Both old spectrum pages scaled every line's peak to its f whatever its width: a stick plot drawn with widths. Physically a line's area is π r_e c f, so a Doppler peak scales as f·λ and a natural one as f/Γ; UV against IR lines and broad against narrow lines were wrong. The broadenings were also shown one at a time instead of as one Voigt profile. The Spectra stage's "absorption" bar used every line in the table, excited lower levels included, as if every level were populated, and its "emission" bar was weighted by the absorption f instead of N_u A hν. Lines with ΔE at the table's 1e-6 eV rounding step (Rb had a "line" at 1.24 m) are now left out. All fixed in the new Spectrum page below.
- **Stages crawled when the CPU was shared.** numpy's BLAS started 4–6 threads per stage on a 20-core Windows PC, which gave no speed-up on LiNaK's few-hundred-row matrices (DHF Na: 31 s on the default threads, 26 s on one). Under a full test run those spinning threads slowed the fitted DHF runs past the tests' 15-minute timeout (25–40 s alone). LiNaK now sets one BLAS thread per process (`OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `OMP_NUM_THREADS`) unless you set them yourself; results are unchanged.
- **Breit–Rabi curves swapped levels at every crossing.** All eigenvalues were sorted together at each field and curve k kept the zero-field label of the k-th lowest level, so wherever two levels of different m_F crossed (22 times below 100 G for Na 3p3/2, throughout the Paschen–Back region of every excited state) the colour and the |F, m_F⟩ label jumped to another level. The Hamiltonian is now solved block by block in m_F, which is exact at every field: each curve is one level and keeps its labels.
- **g_J used g_S = 2.** The Landé formula took the electron spin g factor as 2, so ground-state g_J was 2.0000 instead of ≈2.0023 and every Zeeman slope was 0.1% small (3p3/2: 1.3333 vs measured 1.3341). It now uses g_S = 2.00231930436 and the reduced-mass g_L = 1 − m_e/M, and the bundled constants give the measured ground-state g_J (Na 2.0022960, K 2.002295, Rb 2.00233113, Cs 2.002542; Steck, Vanden Bout et al. Phys. Rev. 165, 88 (1968)).
- **g_I ignored diamagnetic shielding.** The nuclear Zeeman term used the bare μ_I/I from the IAEA table. Inside the atom the electron cloud shields the nucleus (0.4% for Rb, 0.6% for Cs), which moves every field-insensitive point: the 87Rb |1,−1⟩ ↔ |2,+1⟩ magic field came out at 3.2418 G instead of the measured 3.228917 G. The constants files now carry the measured atomic g_I′ (Arimondo, Inguscio & Violino 1977, `_gI_prime`) for Na, 39K, 41K, 85Rb, 87Rb and Cs, used when present; the stage prints which g_I it used. If your data folder has older copies of `<El>_hf_constants.json`, the stage says so: delete them to pick up the measured values.
- **Hyperfine level diagram:** "E1" connectors were drawn between any two consecutive states, including 3p1/2 → 3p3/2 (same parity, not an E1 line); the Zeeman page printed half-integer F and m_F rounded (210Fr, I = 6, showed F = 6 for 11/2).
- **Merged-J levels in the transitions list:** NIST lists the f and g levels from n = 12 as one level (`5/2,7/2`, `7/2,9/2`), and the transitions stage tested the ΔJ rule with the first J only, dropping f → g9/2 lines (for Na, 18 lines between f n = 12 to 20 and 18g9/2 or 6g9/2). Every J of a merged level is now tested. Only Na was affected (Li, K, Rb, Cs and Fr rebuild to identical lists). Na's bundled transitions and lifetimes files are regenerated: the 18g9/2 lifetime drops 12% (it lacked decay channels its 18g7/2 partner had), the f5/2 lifetimes n = 12 to 20 change by under 0.2%. Rerun Transitions, then Lifetimes, Polarizability and Blackbody for your own species data.

### New
- **Orbital page redesign.** Same page shell as Compare (controls rail, tabs, Theme, Export). Tabs:
  - 3D: the WebGL2 volume (or `--render isosurface`), with a cutaway that removes the half facing the viewer.
  - Slice: a 2D cut through or across the quantisation axis, with radial nodes, core radius and nodal lines drawn.
  - Radial: P(r) (or r P(r) on a log axis), up to five states overlaid, with core radius, turning points, nodes and the enclosed probability.
  - Values: n*, model ν, nodes, ⟨r⟩, ⟨r²⟩, ⟨1/r⟩, ⟨1/r³⟩, outer turning point, core radius, probability inside the core and the Le Roy radius for every state.
  - Scaling: ⟨r⟩ and core penetration against n*, with the hydrogenic and n*⁻³ laws.
  - Colour scales can be set by the maximum outside the core, so the valence shell stays visible next to the s-state core peak. Units a₀, Å or nm.
  - Exports: plots as SVG/PNG, the 3D view as PNG, the table and the radial function as CSV, the values as JSON.

The Compare stage writes it with the table data (untick Generate page, or `--no-page`, for the data only); `--pipeline scattering_rate` opens it on the Laser cooling tab. Tabs:

  - **Laser cooling:** for any element and D line:
    - the scattering rate against detuning and intensity;
    - the 1D molasses force;
    - the Doppler temperature against detuning, with the Doppler and recoil limits.

  - **C₆:** the homo- and heteronuclear matrix, as values or as deviations from Derevianko, Porsev & Babb (2010).

- **Feshbach page** (Atomic response > Feshbach resonances, `plots/<El>/<El>_feshbach.html`): one tabbed page in the style of the other pages (rail, theme, Export to SVG, PNG, PDF, CSV) replaces the two-panel plot. The field switches between gauss and mT. Tabs:
  - **Scattering length:** a(B) of each entrance channel, on an asinh or linear axis, with poles and zero crossings marked. For ⁶Li it comes from the coupled-channel table of Zürn et al. (PRL 110, 135301 (2013); `Li_feshbach_table.json`, 0–2000 G), with the narrow 543.29 G line put back analytically. For Cs it comes from published fits: Kraemer et al. (Nature 440, 315 (2006)) for 0–150 G and Jachymski & Julienne (PRA 88, 052701 (2013)) for 490–508, 530–570 and 750–900 G. Between those ranges a product model scaled to meet the fits is drawn dashed. Na, K and Rb use the isolated-resonance formula over the literature poles. For a Fermi gas, 1/(k_F a) is drawn under a(B), with the density as an input.
  - **Cross section & loss:** the thermal cross section ⟨σv_rel⟩/⟨v_rel⟩ with its unitarity limit, the elastic rate, and for bosons the three-body rate L₃n². L₃ = 3Cℏa⁴/m, with the Efimov factor C as an input, capped at the unitarity limit of the gas.

  - **Thresholds:** the ground-state Zeeman levels, with each channel's two-atom threshold and magnetic moment.
  - **Resonances:** B₀, Δ, a_bg, δμ and s_res = (a_bg/ā)(δμΔ/Ē) (Chin et al. 2010), with R* = ā/s_res and open- or closed-channel character; sortable, CSV.

Checks: ⁶Li poles 832.18, 689.68, 809.76 G; Cs a(0) = −2490 a₀ with the zero at 17.0 G; s_res against Chin's Table IV (³⁹K 2.1, Na 0.09, ⁶Li 59). - **Spectrum page** (Visualise > Spectrum, `--pipeline spectra`, `plots/<El>/<El>_spectrum.html`): one tabbed page replaces the Grotrian stage's `<El>_spectrum_levels.html` and the Spectra stage's `<El>_spectra.html`. Every line is a Voigt profile with area π r_e c f: Doppler at the gas temperature with an optional instrument Gaussian, the natural width (1/τ_u + 1/τ_l)/2π and an optional pressure or laser width. Lines narrower than a plotted point keep their area in it, and zooming recomputes the spectrum, so line shapes resolve at any range. Tabs:
  - **Absorption:** cross-section per atom with Boltzmann lower-level populations and stimulated emission; optical depth or transmission of a vapour cell whose density follows the vapour pressure (Alcock, Itkin & Horrigan 1984; Rb at 25 °C 1.29×10¹⁰ cm⁻³), or a density you set; the refractive index n − 1 from the same Faddeeva function.
  - **Emission:** optically thin, N_u A hν with upper levels populated at an excitation temperature (T → ∞ gives equal population per sublevel).
  - **D lines:** D1 and D2 resolved into hyperfine components, with the natural isotope mix (⁶Li/⁷Li, ³⁹K/⁴¹K, ⁸⁵Rb/⁸⁷Rb) and measured isotope shifts (Das & Natarajan 2007, Falke et al. 2006, Banerjee et al. 2003). Shown Doppler-broadened through the cell, or as saturated absorption with Lamb dips and crossovers (positions and widths exact; heights from the weak-saturation estimate without optical pumping).
  - **Curve of growth:** equivalent width against column density, with the thin and damping asymptotes and this cell marked.
  - **Strip:** white light through the vapour and the emission as colour bands, either as a line pattern or physically at a chosen resolution.
  - **Lines:** air and vacuum wavelengths, wavenumber, f, Δf, A, g, source, natural and Doppler widths, peak cross-section; searchable, sortable, CSV.

  The x axis switches between vacuum and air wavelength, cm⁻¹, eV and THz. Air wavelengths use standard air (NIST's formula), above 200 nm. Each tab can be left out (`--no-tab-absorption` … `--no-tab-lines`). The stage reads the lifetimes data only; the D-line tab also reads `<El>_hf_constants.json`. The transitions-only fallback (every f = 1) and the hard-coded D-line fallback are gone, and `--transitions-file` is ignored. For ions, the ground state is the level every other one lies above (Na⁺ 2p⁶; the metastable 3s ³P°₂ was a candidate). The Grotrian stage writes the Grotrian page only; its `--plots` option is still accepted. Checks: Na D2 air 588.99509 nm (NIST 588.9950954); Rb and Cs vapour pressure at 25 °C within 2% of Steck; Cs D2 F=4 → F′=5 at −3757.886 MHz from the centroid (Steck); the curve of growth's thin and damping limits. The browser's physics is tested against the Python (scipy's Faddeeva function) in node. The old pages are no longer written: delete `<El>_spectrum_levels.html` and `<El>_spectra.html` from your plots folder.
- **Hyperfine page** (Hyperfine / Zeeman stage, `plots/<El>/<El>_hyperfine.html`): one tabbed page in the style of the Grotrian, Polarizability and Blackbody pages (rail, theme, Export to SVG, PNG, PDF, CSV) replaces `<El>_hyperfine.html` and `<El>_zeeman.html`. Tabs: **Levels** (each state on its own frequency scale, F levels with their m_F sublevels and g_F, the clock interval), **Breit–Rabi** (several states side by side, curves coloured by m_F or F, energy or dE/dB in μ_B, a weak-field (linear) overlay, high-field |m_J, m_I⟩ labels, a field cursor with a table of every level's energy, slope and low/high-field-seeker status, and the |m_J, m_I⟩ composition of a clicked level vs B), **Transitions** (every ground-state ΔF = ±1 microwave line, single photon and two-photon, as ν − ν₀ vs B with its linear and quadratic Zeeman coefficients and its field-insensitive points; the Zeeman-resolved D lines vs B and as a σ+/π/σ− spectrum at the cursor field with an adjustable linewidth; the zero-field strengths S_FF′) and **Constants** (nuclear data, A, B, C, g_J and g_I with their sources). Field units G, mT, T and frequency units kHz, MHz, GHz switch on the page. Checks: 87Rb and 133Cs clock shifts 575.15 and 427.45 Hz/G² (Steck), 87Rb magic field 3.2289 G (measured 3.228917 G), 87Rb D2 S_FF′ = 7/10, 1/4, 1/20 and 5/12, 5/12, 1/6. The bundled pages are regenerated and the Zeeman pages removed; rerun the stage for your own species.
- **DHF + core polarisation stage** (Structure models > DHF + core polarisation, `--pipeline dhf`): a relativistic one-valence model independent of ORCA. Dirac–Hartree–Fock core in a B-spline basis with a finite nucleus, plus a core-polarisation potential whose cutoff is fitted to the NIST ionization energy (and, by default, the lowest d3/2 and d5/2 levels; `--no-fit-d` turns that off). It writes `data/<El>_dhf.json` with levels, the E1 network (reduced dipoles, f, A), lifetimes, α(0) and α(ω) (`--omega`), j-resolved quantum defects and a comparison with NIST. Accuracy (Na to Fr): D lines within 0.6%, D-line f within 0.4%, α(0) within 1.3%. `--ip` (cm⁻¹) replaces the NIST ionization energy, so the stage runs without NIST files (no d fit, no comparison then). `--n-max` sets the highest n of the levels and lines (default: valence n + 6). The "Quantum chemistry" sidebar group is renamed "Structure models" (ORCA, DHF + core polarisation, Brueckner).
- **Brueckner stage** (Structure models > Brueckner (DHF + Σ2), `--pipeline brueckner`): an energy-dependent core-polarisation model next to the DHF + core-polarisation stage, with its own output `data/<El>_brueckner.json` (same layout as `<El>_dhf.json`: levels, E1 network, lifetimes, α(0), α(ω) with `--omega`, quantum defects, NIST comparison). Levels: frozen-core DHF plus the second-order correlation potential Σ(2)(E) (core polarisation including its non-adiabatic part, plus the exchange term; Johnson et al., arXiv:physics/0310141), solved self-consistently per level. Dipoles: between the Brueckner orbitals, dressed by the core's RPA response at the transition frequency; the core polarisability comes from the same RPA (Li+ 0.1894 … Cs+ 15.82 a.u., matching relativistic RPA to 4 digits), so α needs no table. Fit to NIST (default, tick "Scale Σ2 to NIST"): one scale factor per l, j fitted to the lowest NIST level (s: the ionization energy); an l, j with no NIST level borrows the mean of the nearest l. Every other level is a prediction: Ca+ 4d +0.10% (DHF + core polarisation +0.83%), Sr+ 5d +0.06% (+0.51%), Ba+ 6d +0.11% (+0.7%), Ba+ 4f +0.24%/+0.41% (+4.8%), Na–Cs higher s/p/d within 0.01–0.02%. Lowest-p lifetimes within 0.5% of precision data for Na–Fr, Ca+, Sr+, Ba+ (Cs 6p −0.07%/+0.10%, Fr 7p1/2 +0.07%, Ba+ 6p1/2 +0.14% where DHF + core polarisation gives +1.7%); Cs 6s–6p1/2 4.4993 a.u. (measured 4.5057). `--unscaled` fits nothing: a pure ab initio run that needs no NIST data (s, p levels 1–3% off, inner d up to 28%). `--lmax` sets the virtual orbitals in Σ(2) (default 5). Weak, cancelling lines (Cs 6s–7p) are 4–7% low: third-order corrections are not included, and the DHF + core-polarisation stage does better there. The first run takes 1–8 minutes per species; Σ is kept in `data/<El>_brueckner_cache.npz`, so reruns take seconds to a minute. Checked against brute-force m-scheme sums (Σ(2) and the RPA vertex), Ginges et al. (arXiv:1603.09116, Cs Σ(2) energies) and Roberts et al. (arXiv:2211.11134, Cs DHF+RPA).
- **DHF stage: p levels and the d series as inputs** (default; `--no-fit-p`, `--d-one-level` restore the old behaviour; GUI ticks "No p-level fit", "Fit lowest d only"). The core-polarisation cutoffs of p1/2 and p3/2 are now fitted to the lowest p levels, and the d channel to two NIST d levels (the lowest and the highest pair up to n_valence + 8) through its cutoff and a factor on α_core (the core polarisability a d electron sees is smaller: 0.95 Na, 0.82 K, 0.64–0.65 Cs). Against precision data, the lowest-p lifetimes go from −1.0 to −1.2% to within ±0.3% for K, Rb, Cs (Ca+ 4p1/2 −2.0% → −0.05%), α(0) for Cs −0.9% → −0.5%, Fr −1.3% → −0.8%, and the d series is fixed: Cs 6d +0.20% → −0.06%, K 4d +0.05% → −0.02%, d levels from n_valence + 2 within 0.005%, n = 25 d quantum defects within 0.002 (was 0.013–0.015 low). Fine structure of the fitted p levels is exact (it was +39% Be+, +8% Na). The D lines are then inputs, not predictions. Where the lowest d is an inner (n−1)d that cannot share a potential with the nd series (Ca+ 3d, Sr+ 4d, Ba+ 5d: the α factor would be 0.06–0.2), the stage keeps the lowest-d fit and records why in `inputs.d_fit_note`. A static quadrupole core-polarisation term was tested and made every unfitted level worse, so it is not used.
- **DHF stage for one-valence ions** (`--pipeline dhf Ca_c1`; also Be_c1, Mg_c1, Sr_c1, Ba_c1): the same model with an M2+ core, so Rydberg levels converge on the next limit (Z_ion = 2 sets n* and the quantum defects). Without a NIST export for the ion, the NIST Handbook limit and lowest d levels built into the stage are used (`--ip` and a user export take precedence); core polarisabilities Be2+ 0.0519, Mg2+ 0.48, Ca2+ 3.284, Sr2+ 5.748, Ba2+ 10.426 a.u. Against NIST: resonance lines Mg+ ±0.01%, Be+ +0.4%, Sr+ +0.5%, Ca+ +0.6%, Ba+ +0.6–0.9%, higher s/p/d levels mostly 0.01–0.2%; α(0) Be+ 24.4, Mg+ 35.0, Ca+ 75.6, Sr+ 90.6, Ba+ 122.3 a.u. (references 24.5, 35.0, 75.5, 90.2–91.3, 121–124); 4p/6p lifetimes of Ca+ and Ba+ within 1–2% of the precision measurements. Ba+ 4f is 4–5% off (its 4f orbital half-collapses into the core). `--all` now includes the five ions. Neutral results are unchanged.
- **Structure-model f-values in Lifetimes and Polarizability** (`--model-f dhf` or `--model-f brueckner`, `--model-file`; "Model f-values" and "Model data" in both stages; `--dhf` and `--dhf-file` still work as the old spelling of `--model-f dhf`): lines with no NIST or literature value take their f from `<El>_dhf.json` or `<El>_brueckner.json` (the model's dipole at the line's NIST energy) instead of ORCA, Numerov or Coulomb, with a 5% uncertainty and source "DHF" or "Brueckner" (purple and violet in the spectra). Measured values are never replaced. Two kinds of line are left to the other sources: ground ns → np beyond the resonance doublet (the Cooper-minimum series, where DHF is off by 5–20% and more for Cs p1/2; NIST and the extrapolator cover it) and lines whose radial integral nearly cancels. DHF only reaches as high as it was run: for Na, NIST covers n ≈ 20, so run the DHF stage with `--n-max 30` to replace Numerov above that. Off by default: no existing output changes.
- **Rydberg shifts, series repair (Blackbody stage):** the Na g series no longer jumps. Three causes were fixed: level energies the quantum-defect model built are used at the formula's value instead of the 1e-6 eV rounding (the f-g gap at n = 33 is the size of that step); f-g pairs lost when two rounded energies tied (n = 34, 35, 41, 42, 44, 45) are restored; and an h (l = 5) series from the same model supplies the upward partners g states lacked (the g dynamic shift was -460 to +1400 Hz at n = 25 to 45 and now runs from 2342 to 2396 Hz, towards the 2417 Hz Farley-Wing limit; all g states now close the f-sum rule). `l = h` is added to the angular-momentum table. The data files are not changed; the repair is made when the shifts are computed. Rerun the Blackbody stage to get it. The same repair restores f(5/2,7/2) to 18g9/2 and 6g9/2 pairs that the transitions list drops for NIST's merged-J f and g levels (n = 12 to 20): the 17f5/2 dynamic shift was 490 Hz and is now 2105 Hz, and the f series is smooth.
- **Rydberg shifts, `static_valid`:** each state in `<El>_blackbody.json` now says whether the static Itano formula applies: false where the coupling to a near-degenerate partner exceeds 0.3 of its gap (second-order theory fails) or where over 10% of α(0) comes from partners below k_B T. Most Rydberg states fail, which is the reason the dynamic shift is the one to use there. The Blackbody page marks them and gives the reason; the numbers stay in the file.
- **Blackbody page, written by the Blackbody stage:** the stage's Generate plot tick now writes one tabbed page, `plots/<El>/<El>_blackbody.html`, next to its data; there is no separate Visualise stage and the old per-plot pages (shifts, rates, photoionization, alpha) and the hub are removed. Tick which tabs to include on the stage (`--no-tab-shifts`, `--no-tab-depopulation`, `--no-tab-photoionization`, `--no-tab-rydberg`); units, temperature range and field are options (`--plot-units`, `--plot-t-min`, `--plot-t-max`, `--field`). Temperature, units, n range and field also change live in the page. A tab whose data the run skipped is left out with a message. The reference plots for Li, Na, K, Rb, Cs and Fr are regenerated.
- **Polarizability page** (Visualise > Polarizability page, `--pipeline polarizability_page`): polarizability, magic wavelengths and optical tweezer on one tabbed page, written to `plots/<El>/<El>_response.html`. α(ω) is summed in the browser from the stored transitions, so units (a.u., Hz per W/cm², µK per kW/cm²), wavelength range, trap intensity and cursor wavelength change live; a searchable, paged table shows which lines make up α at the cursor, and magic wavelengths are marked by robustness (circle, diamond, square). The Polarizability and Optical tweezer stages now write data only (their separate plots and the Generate plot tick are gone from the GUI; the command line keeps `--no-plot`). Tick which tabs to build: Polarizability, Magic wavelengths (the differential polarizability Δα and the magic wavelengths), Optical tweezer. Input options: polarizability and lifetimes data; output option: output directory (and Save as).
